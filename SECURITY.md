# Security and privacy

Plenio runs inside ComfyUI on your own machine. This page lists everything it does beyond computing inside ComfyUI's process: what it downloads, which programs it starts, which addresses it talks to and which files it writes.

## Network

- **One download, on first use.** The lyrics ASR model (faster-whisper large-v3, 3 GB, MIT licence) is fetched from Hugging Face when *Transcribe Lyrics* first needs it - from a revision pinned to a full commit hash, with the sizes and the SHA-256 of the weights checked (`resources/assets.toml`, `plenio/core/assets/fetch.py`). `PLENIO_OFFLINE=1` (or `HF_HUB_OFFLINE=1`) turns this off; point `[asset_paths]` in Plenio's `config.toml` at a copy you already have.
- **Model weights** in the templates are offered by ComfyUI's own missing-model dialog, not downloaded by Plenio.
- **Local LLM** talks only to language-model apps on your machine: their default local addresses (`127.0.0.1`: LM Studio, Ollama - which honours `OLLAMA_HOST` -, llama.cpp, vLLM, Jan, KoboldCpp, text-generation-webui, GPT4All, Unsloth Studio), the llama.cpp server it starts itself on a free local port, and the servers you add in `[llm.servers]`. A system proxy is bypassed for these requests. `[llm] other_apps = false` (or `PLENIO_LLM_OTHER_APPS=0`) keeps it to ComfyUI's own `models/LLM` folder. API keys are read from environment variables, never stored.
- No telemetry, no cloud service, no account.

## Programs Plenio starts

- **The lyrics ASR worker** - `python -m plenio.workers.asr` with ComfyUI's own Python, in a separate process so its memory is freed afterwards (`plenio/core/workers/protocol.py`: a fixed command line, no shell). On Windows it adds the CUDA library folders of the installed packages to its own `PATH`, so CTranslate2 finds cuBLAS and cuDNN.
- **A llama.cpp server** for a GGUF file chosen in *Local LLM* - the `llama-server` you installed (or `PLENIO_LLAMA_SERVER`), or llama-cpp-python through `python -m plenio.workers.llama_http` - listening on `127.0.0.1` only and stopped after the answer unless *keep loaded* is on (`plenio/core/llm/runtime.py`).

Plenio installs no Python packages. When a feature needs one (faster-whisper), it names the command for you to run.

## Files Plenio writes

- **ComfyUI's output folder** (`output/plenio` by default): the exported audio, cover art, sheet music PDF and release record - the record also inside the song's FLAC (*project in FLAC*, on by default; off with ComfyUI's `--disable-metadata`), with the same redactions; the stems marked *save* in the Stem Mixer, next to the song in `<name>-stems` (without an export in `output/plenio/stems`).
- **ComfyUI's user folder** (`user/plenio`): your brief templates and creative modes, `config.toml`, and caches (lyrics ASR results, Local LLM answers) that make runs repeatable. The score editor keeps your sound presets in ComfyUI's own user data.
- **The models folder**: the ASR model (`models/plenio/asr`).
- **The temp folder**: a worker's job folder and a llama.cpp server's log while they run, removed afterwards.

## The Plenio Player

The player (`python plenio_player.py`, `python -m plenio.player`, `Plenio Player.bat`, `plenio_player.sh`) is a separate program. ComfyUI never serves it; its **Plenio Player** button calls `POST /plenio/player/open`, which looks for a running player on `127.0.0.1:8765-8769` and, when none answers, starts one with ComfyUI's own Python - a fixed argument list without a shell, in the background, detached so that it keeps running when ComfyUI stops, its output in `player.log` in the player's state folder (`plenio/player/launch.py`). It serves a web page and the songs of the folders you give it (ComfyUI's output folder by default) on `127.0.0.1:8765`. It answers only requests addressed to `127.0.0.1` or `localhost` (no other web page can reach it under a name of its own), serves only the files a release record lists in the record's own folder, and sends no CORS headers, so other web pages cannot read from it or change its state. `--host` opens it to a network; it has no login, so do this only on a network you trust. It writes into the songs' folders only when you remove a song: its files move to `_retired` in the library folder, or are deleted when you choose *Delete permanently* and confirm it - only the files in the song's own folder, and only on a request from the player's own page that names the song twice (JSON, which another site's page cannot send without asking first, and the page's own origin). Your playlists, favourites, play counts, settings, its library cache and the songs' waveforms go to `~/.plenio/player` (or `PLENIO_PLAYER_STATE`). Your Plenio Drop presets are `.json` files in its `visuals` folder: the page reads them (at most 200, up to 256 KB each) and evaluates their formulas with its own small calculator - numbers, names and a fixed list of functions, never script - so a preset someone shares can only draw. *Edit a copy* writes a new file there (never over an existing one), and *Open my folder* shows that folder in the file manager; both only on a request from the player's own page. The folders it reads are chosen on its Settings page and kept in `library.json` there; its folder browser lists the names of folders (never files) of this computer, and only for the player's own page (a request header another page cannot send without asking first); a folder is saved only from the player's own page (JSON, its own origin) and only when it exists. In a folder with *also other music* it serves the audio files no release record owns, their lyrics and covers - files in that folder only - and saves a picture embedded in such a file once into its cache to show it. *Save as a video* sends the video the page encoded to the player in pieces (a request header another site's page cannot send without asking first, and the page's own origin); the player puts it together with the song's own audio file into an MP4 in its `videos` folder with PyAV and serves only the MP4 files in that folder. Unfinished videos are removed after a few hours. *Share as a player* writes one HTML file into its `packages` folder, on a request from the player's own page: the player's page code and, of the songs chosen, MP3s (at most 192 kbit/s), small covers, the timed lyrics and notation, waveforms and optionally the sheet music PDFs, your visuals' settings and preset files and your playlists of those songs - never a release record, a workflow, a FLAC/WAV or a path of this computer. The shared file runs in the recipient's browser without any server: it keeps their playlists and settings in that browser and sends nothing anywhere. *Open the folder* (after a video or a shared player, and in Settings) shows the player's own `visuals`, `videos` or `packages` folder in the file manager - on Windows it starts Explorer itself with that folder (and the new file chosen) as its only argument, without a shell; elsewhere `open` or `xdg-open` - only on a request from the player's own page, and never another folder (`plenio/player/visuals.py`). A second player on a taken port does not start. To find ComfyUI for *Open in ComfyUI* it asks only loopback addresses (`127.0.0.1:8188`, `:8000`, or the one you set); the ComfyUI page takes a song's record only from its own origin or a loopback one. It downloads nothing and talks to no other address (`plenio/player/server.py`).

## Plenio's HTTP routes

ComfyUI serves Plenio's routes under `/plenio/` (`plenio/comfy/routes.py`). They analyse and convert what the editor sends (scores, lyrics, MIDI, the EQ curve) and read the template library and presets. Two write files: `POST /plenio/templates` saves a brief template under a sanitised name in `user/plenio/templates`, and `POST /plenio/export/sheet-music` saves the sheet music PDF of an export - only with the one-time token Export Release created for that file, within 24 hours, only a PDF, only to the name the node reserved. `GET /plenio/export/sheet-music/pending` lists the PDFs still waiting for a page to draw them (their notation and tokens), so a page that opens later can finish them. `GET /plenio/records` lists the release records in the output folder (title, date, file names) and `POST /plenio/records/continue` reads one of them - only a `.plenio.json` inside the output folder - or a record the page sends (read from a `.plenio.json` or from a FLAC by the page itself), to open its song again; both only read. The release record keeps the workflow a run was queued with; secrets are redacted in it as in the prompt (a value a node's key or token input holds is replaced wherever the workflow has it). Like all of ComfyUI, these routes are meant for a ComfyUI that listens on your own machine; if you open ComfyUI to a network, secure it as ComfyUI's own documentation describes.

## Reporting a problem

Please report a security problem through GitHub's private vulnerability reporting on this repository (*Security > Report a vulnerability*); if that is not available, open an issue without the details and ask for a private channel.
